# Data Model

Current schema of the Common Parts Access database (Supabase, PostgreSQL), as of v1.2.0 (October 2026). For how it got here, see [DATA_MODEL_EVOLUTION.md](./DATA_MODEL_EVOLUTION.md) (historical).

There is one database, production, behind every environment. Schema changes are SQL files in `supabase/migrations/`, applied by the human. Every table in `public` has RLS enabled.

---

## Entities at a glance

```
brands ─┐
        ├─< products >─┐                      categories (tree: parent_id, path)
        │      │       │                            │
        │      │       └─< product_references       │
        │      │                                    │
        │      └─< part_products >── parts >────────┘
        │              │               │
        │              └─ print_reports┤
        │                              ├─< part_files
        │                              ├─< part_views / part_downloads (anonymous)
        │                              ├─< part_likes / part_comments (hidden, #322)
        │                              └── licenses (license_id, source_license_id)
        │
products ─< part_requests        user_profiles ─< parts (user_id)
search_misses (standalone)       curation_rejections (standalone)
feedback (agent pipeline)        source_platforms (reference list)
```

A part fits one or more products through `part_products`. A part has no brand of its own: its brands are the brands of the products it fits (#315). A product belongs to exactly one brand and one category.

## Catalog

### `parts`
A spare part record (renamed from `models` in #314).

| Group | Columns |
|---|---|
| Identity | `id`, `name`, `slug` (unique), `description`, `part_name`, `part_number`, `tags`, `category_id` |
| Owner | `user_id` → `user_profiles` (the account that added it); null once that account is deleted (`ON DELETE SET NULL`, #178) |
| Lifecycle | `status`: `draft` / `published` / `archived` |
| Origin | `origin_type`: `original` / `curated` / `manufacturer`; `file_hosting_type`: `hosted` / `link_out` |
| Attribution | `source_url`, `source_platform`, `source_published_at`, `original_author`, `original_author_url` |
| Licensing | `license_id` (publication license), `source_license_id` (license at the source) → `licenses` |
| Print data | `material`, `color`, `dimensions` (jsonb), `print_settings` (jsonb), `estimated_print_time`, `estimated_material_usage`, `instructions`, `notes` |
| Media | `thumbnail_url`, `images` |
| Trust | `verification_status`: `unverified` / `author_tested` / `community_validated` / `certified` |
| Counters (trigger-maintained) | `view_count`, `download_count`, `like_count`, `makes_count` |
| Curation | `curation_checklist` (jsonb), `needs_verification`, `needs_print_settings`, `needs_photo`, `needs_instructions`, `needs_category`, `needs_legal_review`, `legal_review_justification` |
| Upload | `originality_attested`, `originality_attested_at` |

Publication rules per track are in [PUBLISH_FLOW.md](./PUBLISH_FLOW.md), [UPLOAD_FLOW.md](./UPLOAD_FLOW.md) and [CURATION_TOOL.md](./CURATION_TOOL.md).

### `products`
A commercial product a part fits ("OneBlade Pro"). Flat: no families or variants (#264).

- `id`, `name`, `slug`, `brand_id`, `category_id`, `description`, `release_year`, `discontinued`, `image_url`
- `parts_count`: published parts linked to it (trigger-maintained)
- `open_requests_count`: open `part_requests` rows (trigger-maintained, #321)
- `is_listed`: generated, `parts_count > 0 or open_requests_count > 0`. The single visibility predicate for public listings.

Products are created during publishing, guarded against normalized-name duplicates at the API layer (#279).

### `product_references`
The values a product is known by (#316): manufacturer references, regional commercial names, barcodes.

- `value` (as displayed), `normalized_value` (generated by `normalize_product_reference()`: uppercase, no spaces, hyphens, slashes or dots)
- `type`: `manufacturer_ref` / `commercial_name` / `ean`
- `region` (ISO 3166-1 alpha-2, null = every region), `language` (BCP 47)
- `source`: `curation` / `search` / `import`
- `status`: `pending` / `validated` / `rejected` (#320). Only `validated` rows are publicly readable.
- Unique on (`product_id`, `normalized_value`, `type`).

See [PRODUCT_COMPATIBILITY.md](./PRODUCT_COMPATIBILITY.md).

### `part_products`
Part–product compatibility. Primary key (`part_id`, `product_id`).

- `evidence_level`: `declared` / `confirmed` / `disputed` (#317)
- `works_count`, `works_with_adjustments_count`, `does_not_work_count` (#318)

All four columns are server-owned: clients may only write `part_id` and `product_id`.

### `brands`
`id`, `name`, `slug`, `description`, `logo_url`, `website_url`, `founded_year`, `country`, `verified`. Read-only in the app: brands are curated in the Supabase dashboard.

### `categories`
A tree: `parent_id`, `level`, and a materialized `path` ending with a slash (`/kitchen/cooker/`), used for subtree prefix checks. Also `name`, `slug`, `description`, `icon`.

### `licenses`
`spdx_id`, `name`, `short_name`, `url`, and the flags `allows_redistribution`, `requires_attribution`, `allows_commercial`, `is_copyleft`, which drive hosting eligibility (`isHostableLicense` in `lib/utils/licenses.ts`).

### `source_platforms`
External platforms parts come from: `slug`, `name`, `base_url`, `logo_url`, `import_supported`, `active`.

### `part_files`
Files attached to a part: `filename`, `original_filename`, `file_type`, `file_size`, `file_category`, `upload_path` (storage path, source of truth), `file_url`, `checksum`. Storage buckets keep their historical ids `model-files` and `model-thumbnails`. See [FILE_DOWNLOADS.md](./FILE_DOWNLOADS.md).

## Evidence and demand

### `print_reports`
Whether a printed part worked on one compatible product (#318). One row per reporter per part–product pair; reporting again replaces the earlier report.

- `result`: `works` / `works_with_adjustments` / `does_not_work`
- `product_reference_id` (optional), `comment` (optional, not public)
- `reporter_hash`: SHA-256 of a random cookie id, or of the user id when signed in. Never an IP address.
- `user_id` (nullable, `ON DELETE SET NULL`)

RLS on with no policy: written only through `submit_print_report()` by the service role.

### `part_requests`
Demand for a part on a product ("Request this part"). `product_id`, `raw_query`, `description`, `user_id` (nullable), `page_url`, `status`: `open` / `fulfilled` / `dismissed`, `fulfilled_by_part_id`. Never creates a GitHub issue.

### `search_misses`
Zero-result searches submitted on `/search` (#320): `raw_query`, `normalized_query` (generated), `locale` (from Accept-Language), `created_at`. No IP, user id or session id. RLS on with no policy: inserted by the service role.

### `curation_rejections`
Sources rejected in the curation tool: `source_url`, `reason`, `failed_criteria`, `created_by` (nullable, `ON DELETE SET NULL`).

## Users and pipeline

- `user_profiles`: `id` (= `auth.users.id`, cascade delete), `username`, `display_name`, `bio`, `avatar_url`, `website_url`, `location`, `reputation_score`, `verified_maker`. Created by the `on_auth_user_created` trigger, see [USER_PROFILE_SETUP.md](./USER_PROFILE_SETUP.md).
- `feedback`: entry point of the agent pipeline, see [DEV_STRATEGY.md](./DEV_STRATEGY.md#database-schema-supabase).

On account deletion (#178), foreign keys to `user_profiles` behave as follows:

| Column | On delete |
|---|---|
| `parts.user_id`, `part_likes.user_id`, `part_comments.user_id`, `curation_rejections.created_by` | `SET NULL` (published parts stay, anonymized) |
| `feedback.user_id`, `part_requests.user_id`, `print_reports.user_id` | `SET NULL` |
| `collections.user_id` | `CASCADE` (`collection_parts` cascades from `collections`) |

`DELETE /api/users` first deletes the user's unpublished parts and their files, and the avatar, then calls `release_storage_ownership(p_user_id)` (security definer, service role only), which clears `owner` / `owner_id` on the user's remaining Storage objects: Supabase Auth refuses to delete a user who owns Storage objects. The `user_profiles_delete_unpublished_parts` trigger (`BEFORE DELETE` on `user_profiles`) deletes any unpublished part still owned by the user, so only published parts outlive their owner. See [ACCOUNT_DELETION_POLICY.md](./ACCOUNT_DELETION_POLICY.md).
